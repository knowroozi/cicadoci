# CCD-49 Linear Done Log – Decision Record

## Why keep a log of Linear "Done" tickets in Git?

- **Traceability** – Each day we capture the state of all completed tickets. The JSON file becomes a permanent, append‑only audit trail of what was shipped.
- **Owner‑level descriptions** – The script preserves the full `description` field for each issue (D5). This keeps the context that the ticket owner entered, without having to query Linear later.
- **No new runtime dependencies** – The script only uses the Go standard library and the existing Linear GraphQL endpoint. Adding the log does not increase the repository's build‑time footprint.
- **Daily PR per‑day workflow** – The GitHub Actions workflow runs each day (or on `workflow_dispatch`). It writes the updated log to a dedicated branch (`automation/linear-done-log`) and opens/refreshes exactly one PR to `master`. This gives humans a clear, reviewed change set and avoids automatic merges.
- **Human‑controlled release** – The workflow only opens or refreshes one PR on `automation/linear-done-log`; nothing auto‑merges, and a human reviews and merges it. Operator setup is in `docs/linear‑done‑log.md`.
